Forth

Private repo · Expo, React Native, TypeScript, Skia, RevenueCat, iOS Family Controls

An iOS app for managing compulsive urges, built solo. I wrote the onboarding funnel, the games, the canvas engine they run on, the native Screen Time blocker, and the on-device data layer.

The stack

Expo SDK 54 with React Native and TypeScript, using Expo Router route groups to keep onboarding, paywall, and paid tabs separate. RevenueCat for billing, PostHog for analytics, expo-sqlite for state, Reanimated and Gesture Handler for interaction. Around 65 files of pure-logic tests under vitest. The blocker is a native module over iOS Family Controls and Managed Settings, shipped with two app extensions.

Things I deliberately did not install: Superwall, Sentry, Rive, MMKV. Earlier notes in the repo recommended all four. None of them earned a place once I looked at what they would actually do here.

Writing the canvas engine

I built the engine on React Native Skia rather than pulling in a game library. Two of the six games run on it. The other four are ordinary React Native views, and that split is deliberate: Skia canvases do not flush on Expo web, so keeping most games as plain views means most of the app stays checkable in a browser and only two need a device on the desk.

The games have to be visuospatial, which is a product constraint that decides engineering work. The evidence the app rests on is about occupying visual working memory, and in that literature verbal and numeric tasks are usually the control condition. A word scramble would be a perfectly good game and the wrong one. I wrote that constraint into the repo docs so it survives me forgetting it.

Choosing not to build a backend

There is no server. State is SQLite on the device, migrated across from an earlier SecureStore layout I outgrew. No accounts, no sync, nothing to breach.

Analytics pass through an allowlist in a sanitize step, so an event can record that an onboarding step completed but never what was answered. Adding an event means editing the event definitions and the allowlist in the same commit. That friction is intentional, and it is the kind of thing that decays the moment it becomes optional.

The native side

Family Controls needs a managed entitlement from Apple and a signed custom build, so none of it runs in Expo Go, where the blocker falls back to a simulation that looks convincing and does nothing. Apps and categories picked through Apple's Screen Time picker get a custom shield screen. Adult websites go to Apple's own web content filter instead, because Apple exposes no adult-specific token to shield and the alternative was blocking every site on the internet.

Two extensions ship alongside the app, one drawing the shield and one handling its button. An extension cannot read the app's database, so the shield screen gets its content through a shared App Group.

The ios directory is generated by prebuild and gitignored, which means it goes stale without saying anything. I re-run prebuild after any change to the native plugin, and I check entitlements against the signed build with codesign rather than trusting what the source says they should be.

A test that checks copy

The blocker is easy to switch off by design, so the app cannot honestly promise outcomes. Rather than leave that to discipline, a vitest file asserts it against the paywall copy. It doubles as coverage for App Store guideline 3.1.2, which wants the thing being purchased named plainly. Putting a test on prose is odd and it has caught real regressions.
