Crisis Analysis

Source · Python, PyTorch, BERT, spaCy, Dash, Docker

A live pipeline over the Bluesky firehose that classifies posts as crisis-related, then pulls out the disaster type and where it is happening. I worked on the ingestion, the model serving, and the container setup the team developed in.

The stack

PyTorch with a BERT sequence classifier fine-tuned on labeled crisis data. A spaCy pipeline built around a transformer-based NER model trained to tag disaster entities, with an entity ruler and sentiment scoring alongside it. The atproto client for the firehose subscription, GeoNames data for location resolution, Dash for the dashboard, and Docker around all of it.

A cheap gate in front of the expensive model

BERT runs first as a binary classifier, and only what passes goes on to NER, gazetteer lookup, and sentiment. Almost nothing on a public firehose is crisis-related, so putting the cheap model first keeps the transformer pipeline off the overwhelming majority of traffic.

Preprocessing strips links, hashtags, mentions, and punctuation before tokenizing, matching how the training data was cleaned. Getting that out of sync is the sort of bug that costs accuracy without ever throwing an error.

Location strings then resolve against a GeoNames US gazetteer loaded into a dictionary at startup, which turns a bare "Asheville" into a city, state, region, and country.

Separate processes for the scraper and the model

Each runs as its own server with its own log. The firehose does not slow down for inference, and anything that blocks the read loop loses posts that are simply gone. Splitting them lets the reader stay at the head of the stream while the model works through whatever has piled up. The scraper uses multiprocessing internally with a lock around the CSV writes.

Bind mounts instead of baking code into the image

The image carries Python 3.12 and the dependencies. The code and data come in as bind mounts rather than COPY, so editing a file on the host changes it inside the container with no rebuild, and adding training data does not invalidate the image. The container command is sleep infinity, and Jupyter, Dash, and the scrapers all get started by hand inside it.

The goal was giving everyone on the project an identical environment, not deploying anything. Debugging one spaCy and PyTorch install beats debugging a different one per laptop.
