Voice Assistant

Source · Python, OpenAI, Whisper, FastMCP, Google APIs, Supabase, iOS

A voice assistant that does things in your actual accounts rather than describing what you could do. You talk, it transcribes, and the model can create a calendar event, draft or send a Gmail message, add a task, or look up a place or the weather, then tell you what it did.

How the tools reach the model

The Google work is plain Python, one module per surface: calendar, gmail, tasks, maps, weather. Those functions are wrapped by a FastMCP server that runs in-process, and a bridge hands the tool list to the OpenAI client and drives the call loop.

Going through MCP for something living in the same process looks like pure overhead, and the reason it is there is the boundary. Tool definitions and their schemas sit in one place, the agent code never imports a Google client directly, and the server can be pointed somewhere else or moved out of process later without the agent noticing. Google auth is a service account with domain-wide delegation, configured in config.json with environment variables available as per-deployment overrides.

Voice and memory

Recording happens locally and transcription goes through Whisper. Sessions and user context live in Supabase behind a small repository layer, so a conversation keeps its history and the assistant knows who it is talking to across sessions rather than starting cold every time.

Surfaces

The same backend is driven three ways: a Flask server, command-line scripts for running the agent or transcribing a file on its own, and a native iOS client that lives in the same repo. Each Google tool also has its own test script, which matters more than usual here. When a calendar call fails it is rarely the model's fault, and being able to exercise the tool without the agent in the way is the difference between a five-minute fix and an afternoon.
