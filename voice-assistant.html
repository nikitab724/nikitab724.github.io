Voice Assistant

Source · Python, OpenAI, Whisper, FastMCP, Google APIs, Supabase, iOS

A voice assistant that operates on real accounts rather than describing what you could do. I built the agent loop, the tool layer, the storage, and an iOS client on top of the same backend.

The stack

Python with the OpenAI SDK, Whisper for transcription, FastMCP for the tool server, Google's API clients for Calendar, Gmail, and Tasks, and Supabase for session and user context. A Flask server and a set of CLI scripts drive it. The iOS client lives in the same repo.

MCP for tools in the same process

The tool server runs in-process with the agent, which makes MCP look like pure overhead. I used it for the boundary it forces. Tool definitions and their JSON schemas live in one place, the agent code never imports a Google client directly, and pointing the bridge at an out-of-process server later is a config change instead of a refactor.

It also meant the workflow modules stayed plain Python functions, one per surface, testable without an agent anywhere near them.

Auth and config

Google auth is a service account with domain-wide delegation. Settings live in config.json with environment variables as per-deployment overrides, so the same checkout runs against a different calendar or delegate without edits to tracked files.

Testing tools without the agent

Every Google tool has a standalone test script. When a calendar call fails it is almost never the model's fault, it is a scope, a delegation, or a malformed payload. Being able to run the tool on its own turns that into checking one thing instead of bisecting a whole agent loop with a nondeterministic component in the middle of it.
